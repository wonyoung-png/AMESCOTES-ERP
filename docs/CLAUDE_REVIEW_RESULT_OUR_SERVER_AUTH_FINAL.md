2026-10-12 공통 읽기 전용 실행기 실제 검토, **USD 0.38**. 이번 인증 검토 총 **USD 2.19**(0.43+0.36+0.58+0.44+0.38).

## Claude 판정

P0 없음, P1 하나: 자동 배포는 Caddyfile 복사 후 docker compose up -d caddy만 실행해 파일 내용 변경을 실행 중인 Caddy가 다시 읽는다는 보장이 없다. OAuth 전에 명시적 reload→실제 config 확인→모의 query log 검사 필요. 이는 코드 정적 검토이며 Claude는 테스트/운영 명령을 실행하지 않았다.

## 반영 및 운영 경계

- 운영 인벤토리 체크리스트에 **검수자 Claude가 caddy reload로 적용하고 실제 config와 모의 로그 검사 후 최초 OAuth** 순서를 추가했다. 현재 운영에 reload됐다는 판정은 하지 않는다. 수동 ERP 앱 배포나 운영 DB 적용을 Codex가 수행하지 않았다.
- P1은 운영 적용 단계에서 확인해야 할 조건으로 남는다. 문서 수정만으로 실행 중인 프록시가 바뀌었다고 주장하지 않음.
- 권한/토큰 분리, 로그 필터 문법·4사이트 범위, 현재 우리 서버와 외부 앱 metadata 구분, 운영 미적용 표시는 문제 없음.
- 리뷰 중 테스트 결과 누락 지적은 후속 실검증으로 보완: 명시적 단위 client/server/shared/scripts719/719, 격리 SQL54/54, 신규 인증4/4, tsc·build·diffcheck 통과. 실브라우저 전체통합 runtime 미설정의 실패는 별도이며 실행 성공으로 합산하지 않는다.
- P2: Caddy 오류 로그는 access encoder와 별도라 콜백 중 upstream 장애 시 URI 누출 가능; 최초 인증은 건강한 앱·설정 확인 후만 진행. code는 일회용/클라이언트 secret 없으면 교환 불가이나 안전검수에서 이를 숨기지 않음.
- 고정 callback은 이번 승인된 우리 ERP 도메인과 개발자센터 redirect의 정확한 일치를 위한 보안 경계다. 사용자 입력/임의 env host로 인증키를 전송하지 않는다. 향후 도메인 이전 시 별도 승인·검증 필요.
