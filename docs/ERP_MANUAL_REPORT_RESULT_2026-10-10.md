# 비서실 수동 팀 점검 결과 연결

## 반영
- ‘지금 점검’ 결과를 정상 보고·보고 작성 실패·저장 실패로 분리해 표시한다. 실패 팀 이름을 안내한다.
- AI 보고 실패의 규칙 기록은 저장되더라도 정상 보고 수에 포함하지 않는다.
- 일부 팀 저장 실패는 AgentRunFailure에 이미 저장한 보고와 실패 팀을 보존한다. API는 503/partial_agent_run 및 분리된 결과를 반환한다. 다른 내부 오류는 기존 500 처리다.
- 성공·실패·응답 유실 뒤 모두 현재 요약을 다시 읽는다. 이미 저장된 팀 보고를 놓치지 않으며, 최신 조회 실패도 안내한다.
- 안내는 다시 그려지는 view 밖에 남긴다. 점검 중 다른 탭으로 이동했다 돌아와도 전체·개별 점검 버튼 잠금과 경과 시간이 유지된다.
- 요약 조회 순번을 보호한다. 늦은 과거 성공/실패 응답은 최신 데이터·오류 화면을 덮지 않는다.
- 화면 배치·폰트·색상 개편 없음. 기존 화면에 결과 상태 안내만 추가한다. 직원 잠금·법인원장·발주 연동 변경 없음.

## 검증과 한계
- 실제 HTML·인라인 처리기를 브라우저로 실행하고 API는 메모리 fixture로 대체한다. 정상·AI 작성 실패·일부 저장 실패·깨진 응답·요약 조회 실패·탭 이동 중 재전송 방지·늦은 성공/실패 응답 차단을 검증한다.
- 실제 runAgents 저장 실패는 합성 HTTP로 재현하며, 에러에 실패 팀이 보존되는지 확인한다. 결과 집계 helper는 정상/AI 실패/저장 실패 혼합 사례로 검증한다.
- API 라우터의 인증·실제 DB·실모델까지 한 번에 실행하는 운영 E2E는 아니다. 기존 대표 전용 인증 정책은 수정하지 않는다.
- 폰트 CDN은 브라우저 fixture에서 빈 CSS로 대체한다. 외부 통신 없이 UI 동작만 검증하며 폰트 시각 품질 검증을 의미하지 않는다.
- 수동 재점검은 새 보고 기록을 추가한다. 자동 재전송·직원 메시지 발송·실제 업무 테스트 데이터 입력은 하지 않는다.
- 페이지 내 점검 잠금은 같은 브라우저 화면의 중복 클릭 방지다. 여러 기기 중복 실행은 기존 서버 프로세스 잠금에 따르며 분산 잠금을 추가하지 않는다.
- 과거 그래프 agent/report/work 후보를 현행 agents.ts·ceo.ts·ceo-console.html과 대조했다. 그래프 예산 600토큰, 별도 모델 호출 없음.
