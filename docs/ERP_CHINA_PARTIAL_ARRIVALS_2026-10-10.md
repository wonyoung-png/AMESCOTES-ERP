# 중국→한국 부분 도착 — 구현·격리 검증

## 업무 규칙

- 중국 출고 시 보유재고를 한 번 차감하고 이동을 생성한다. 도착 확인은 생산 입고·미지급·국내 EZ 재고를 만들지 않는다.
- 이동마다 발송 수량, 누적 도착 수량, 남은 운송 수량을 표시한다. 전체 재고의 운송 중 위치도 발송 전체가 아닌 잔량을 사용한다.
- 회차별 도착 수량·물류 입고 근거·도착일·기록자·기록 시각을 서버에 저장한다. 일부 도착은 `in_transit`, 누적 도착=발송일 때만 `received`다.
- 새 도착은 고정 `arrivalId`와 `receivedQty`가 모두 필요하다. 동일 ID·동일 본문 재시도는 원본 반환; 같은 ID의 변경 본문·다른 이동 연결은 거절한다.
- 이동 잠금 아래에서 최신 잔량을 검사한다. 화면의 오래된 잔량을 믿고 초과 저장하지 않는다. 회차와 누적량을 한 트랜잭션으로 저장한다.
- 기존 전량 도착은 `received_qty=qty`로 보존하고 가짜 회차 이력은 생성하지 않는다. 구형 미확인 전량 요청은 본문을 바꾸지 않고 재시도할 수 있다. 이미 일부 도착한 이동에는 구형 전량 요청을 적용하지 않는다.
- 입력을 뒤늦게 등록하더라도 완료 요약은 가장 최근 실제 도착일과 그 근거·기록자를 사용한다. 모든 회차는 개별 날짜 그대로 보존한다.
- 응답 유실 시 같은 탭·계정·브랜드의 첫 요청을 저장·복원한다. 다른 탭/기기·탭 종료 후 동일 보장은 없으므로 근거를 확인해야 한다.

## 적용 경계

- `migration_china_stock.sql` 다음에 `migration_china_partial_arrivals.sql`을 적용한다. 가산형 스키마 변경, 기존 행 삭제·테이블 삭제 없음. 부분 도착 사용 후 기본 중국 이동 마이그레이션만 재실행하면 안 된다.
- 테스트 스택은 `codex.e2e=20261010`, 내부망, 공개 포트 없음, tmpfs DB다. 생산 행·실제 계정 해시·서명키·모델 API 키를 복제하지 않았다.
- 운영 반영은 배포 잠금·기존 테이블/함수 백업·마이그레이션·서버 재시작·스키마 재적재·건강 상태 확인으로 별도 수행한다. 이 문서는 배포 전 구현 검증 기록이다.
- 전면 UI/UX, 이지어드민 동일 시각 실재고 대조, 법인 원장 분리, 직원 개방, 은행/외부 회계 연동은 제외한다.
- graphify 후보를 현재 SQL/API/화면과 대조하고, karpathy-guidelines의 기존 계약 보존·최소 변경 기준을 적용했다.
