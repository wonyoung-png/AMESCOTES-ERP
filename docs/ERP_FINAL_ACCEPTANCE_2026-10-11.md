# ERP 최종 통합·대표 피드백 진입 기준

## 대표 결정
2026-10-11: 수정 ERP의 실제 업무 흐름·누락·중복·비서실 연동을 Claude Code와 최종 점검하고, 필요한 수정·재검증·최종본 업데이트 뒤 대표가 피드백한다. 운영 적용은 대표가 선택한 **「코드 통합·검증 후 클로드가 운영 적용」**을 따른다. Codex의 운영 배포·DB 적용·실제 카페24/Shopify 쓰기 권한으로 해석하지 않는다.

## 통합 기준
- 별도 `AMESCOTES-ERP-council`의 `product-registration`에서 기존 577e9f7과 `erp-flow-optimization`의 2cfe619까지 통합했다. 기존 flow-opt checkout과 운영 데이터는 변경하지 않았다.
- server/index의 상품 등록·자사몰관리와 샘플·불량·경비 라우트를 모두 유지했다. ceo/console의 브랜드 생산 의뢰 판단·최신 근거와 대표 전용 자사몰 점검을 모두 보존했다.
- watch의 운영 업무 점검과 구독 갱신 기준을 모두 유지했다. 테스트 픽스처는 두 브랜치의 실제 요청 테이블 합집합을 사용한다.
- 대표 업무함 테스트는 실제 자사몰 결정 함수 의존성을 포함하도록 수정했다. 브랜드 발주 저장 테스트는 새로 추가된 빈 deep-link 경로의 hook 의존성을 지원했다. 기존 테스트를 삭제하거나 기대 결과를 느슨하게 하지 않았다.

## 피드백만 남았다고 보고할 조건
1. Claude의 코드 수정 필수 지적을 해소하고 통합본의 회귀·타입·빌드를 다시 통과한다.
2. Claude 운영 담당이 대상 commit·현재 운영 변경·백업·마이그레이션 선행 조건을 확인하고 한 번만 적용한다. 직원 공개는 계속 차단한다.
3. 개발실·팀장·생산팀의 실제 인증된 테스트 계정으로 샘플 등록→사진 완료→팀장 업무함/수락→단건·월합산 기존 명세표→상품/BOM→공장 선택·납기→작업지시→부분 입출고→승인된 불량 차감→월말 지급계획→대표 원본 근거를 검수한다.
4. LUMEN/AETALOOF는 해당 브랜드 샘플/생산만 보이고 OEM 접근은 차단되며, 비서실 경로·메뉴·자료는 대표에게만 보이는지 서버까지 확인한다.
5. 기존 원가 양식·품목 사진·공장원가/총원가·견적 설정/실제 마진·본사 제공 자재·패키지 선택이 보존됐는지 대표 요구 목록과 대조한다. 중국 외부 원가 접수/승인 및 작업지시 불변 버전·전송 성공 확인의 기존 미구현 범위를 숨기지 않는다.
6. 상품 등록 인계서의 실제 채널 5개 시나리오를 운영 담당이 검수한다. 정확한 hardcap·권위있는 실입고 자동 종료 미지원은 운영 기능 완성으로 세지 않는다.

## 필수 지적 수정 내역
- 샘플 수락 담당은 `sample_workflow_settings`에 대표가 명시 설정한다. `PATCH /api/samples/workflow/settings`는 대표만 호출할 수 있다. 미설정 시 기존 대표 인증 기준인 활성 `role=대표`, `email=wonyoung@atlm.kr` 계정이 정확히 1개일 때 기본 배정하며, 없거나 복수이면 실패한다. 직원 직책/이름을 추정하지 않는다. 운영 담당이 실제 개발 팀장 ID를 설정해야 하며 아직 설정 관리 UI는 없다.
- 공장 전달/컨펌은 해당 네 필드만 조건부 변경한다. 일반 발주 저장은 원본 `persistedUpdatedAt`이 일치해야 하며 기존 발주를 신규 INSERT로 덮지 않는다. 충돌 시 재조회 후 수정한다.
- 작업지시서 연속 입력은 해당 초안의 직전 저장이 성공한 버전만 이어받는다. 직전 실패는 후속 초안 저장을 막고, 다른 발주의 버전을 섞지 않는다. 실제 부모 함수 대기열 테스트 4건을 추가해 연속 성공·앞선 실패·다른 사용자 충돌·다른 발주 이동을 검증했다.
- 샘플 원가를 청구 단가로 자동 사용하지 않는다. 명시 청구 가격을 입력해야 한다.
- 완납 시 연결된 수락 샘플도 수금완료로 갱신한다. 부분 수금·재시도·잘못된 양방향 연결·금액 차이·실패 시 전체 롤백을 실제 격리 SQL로 확인했다.
- 과거 미분류 불량은 미확정으로 표시한다. incomplete 자사몰 보고는 최신 정상 보고/대표 확정 판단 근거에서 제외한다.

## DB 적용 주의
workflow 문서의 선행 알림/지급/입고 RPC→purchase material spec→sample workflow→defect approval(기존 지급 RPC 뒤)→expense payable 순서와 product registration DB15의 team_agent_runs·erp_server 권한을 함께 확인한다. `migration_sample_settlement.sql`은 **sample workflow와 migration_settlement_atomic.sql 이후**에 적용한다. 지급/수금 기본 마이그레이션을 뒤에 재적용해 최신 보호와 샘플 연결을 덮지 않는다. 실제 DB DROP/기록 DELETE·레거시 승인 추정은 금지다.

## 현재 인계 상태
코드 통합·필수 지적 수정·로컬 검증 및 Claude 정적 재검토 통과. product-registration 브랜치로만 커밋·push해 운영 담당에게 인계한다. 운영 검수·미구현 업무 조건 확인이 남아 있어 아직 「대표 피드백만 남음」으로 판정하지 않는다. 최종 운영 업데이트는 Claude 담당이다.
