# ERP 실무 흐름과 비서실 연동 검수

2026년 10월 11일 기준. 대상은 검토용 시안이 아니라 현재 저장소의 실제 ERP 화면과 서버 업무 처리 코드입니다. 대표님이 비서실만 보고 회사를 파악하려면 실무자가 원본을 한 번 입력한 뒤 담당자 확인, 다음 업무, 팀 공유, 대표 보고까지 이어져야 합니다.

## 현재 결론

브랜드 생산 의뢰 승인 대기, 출고 잔량, 최근 품목과 BOM·자재 저장, 자재 구매 및 중국 거점 재고·부분 도착을 비서실이 원본에서 조회하도록 로컬 코드를 보완했습니다. 직원이 같은 내용을 업무 카드로 재작성할 필요는 없습니다. 모든 ERP 업무의 실사용 완료 판정은 아직 아니며, 운영 서버 배포와 실제 계정·DB·외부 AI 검증은 남아 있습니다.

Claude Code가 실제 소스 16개를 독립적으로 검토했고, Codex가 주요 지적을 현재 코드로 대조했습니다. 아래의 소스 연결 확인은 실제 직원 계정, 운영 DB, 외부 서비스와 AI를 끝까지 실행한 통과 판정이 아닙니다.

| 업무와 팀 보고 관련 검사 | 39건 통과 | 합성 데이터와 대체 HTTP 응답 사용 |
| 승인 버전과 알림, 입출고, 재고, 팀 협의, 구매 저장 검사 | 66건 통과 | 실제 운영 DB와 AI 호출 검증 아님 |

| 실제 AI 보고와 PMS, 구글 캘린더 | 미확인 | 이 검수에서 외부 전송과 실제 AI 호출 미실시 |

최초 검수에서는 기존 자동검사 105건이 통과했습니다. 보완 후에는 신규 회귀검사를 포함해 135건을 다시 실행했고 전부 통과했습니다. 타입 검사와 프런트·서버 빌드도 통과했습니다. 대체 DB 응답과 합성 계정을 사용한 결과이므로 운영 DB·외부 AI 통과를 뜻하지 않습니다. 운영 데이터 변경, 배포, 메뉴 삭제, 직원 메뉴·API 권한표 변경은 수행하지 않았습니다.

대표 비서실은 기존 비공개 접근 경계를 유지합니다. 재무 실자료, 법인원장, 직원 역할별 권한표와 브랜드별 전체 접근 재설계는 기존 보류 상태입니다. 신규 입력 메뉴나 복제 업무 카드를 추가하지 않았으며 기능 삭제는 없습니다.

Claude의 변경 코드 재검수에서 작성 상태 의뢰 누락, 승인 탭 전환 누락, 중국 입고 중복 계산, 대표 요청 우회 종료, 샘플 연결 의도 잔존을 추가 확인했고 각각 수정과 회귀검사를 추가했습니다. 수정 이후 최종 판정은 Codex의 코드 대조와 자동검사 기준입니다. 실제 운영 DB의 샘플 연결 컬럼·기존 링크 상태와 직원별 접근 범위는 배포 전 확인해야 합니다. 오래된 미결 구매는 기간만을 이유로 숨기지 않으며 신규 저장 이력과 별도 표시합니다.

## 최초 검수에서 확인한 보완 대상

### 브랜드 의뢰 승인 대기 조회

`server/ceo.ts:206`의 대표 자료 수집과 `server/watch.ts:47`의 감시 표 목록에는 브랜드 발주 묶음 승인 대기가 포함되지 않습니다. `server/brand-workflow.ts:27`에는 대표 승인 API가 있고, `supabase/migration_brand_workflow_atomic.sql`에 승인과 발행 처리가 있으나 해당 파일에는 업무 카드와 알림 생성 연결이 없습니다.

대표가 비서실만 볼 경우 승인할 생산 의뢰를 놓칠 수 있습니다. 원본 의뢰에 승인 대기 상태를 한 번 저장하고 비서실에서 그대로 조회하는 방향이 필요합니다. 다른 운영 SQL 트리거와 배포 DB의 추가 연결 여부는 미확인입니다.

### ERP 원본 변경의 보고 누락

`server/watch.ts:47`은 생산 발주, 입고 이력, 샘플, 청구와 정산, 기획전 등의 일부 표를 조회합니다. 품목, BOM, 자재 기준정보, 구매 거래, 중국 재고 원본은 해당 감시 목록에 없습니다. `server/ceo.ts:311`의 질문 경로도 업무 카드와 현재 감시 요약 중심입니다.

원가나 자재 단가가 바뀌어도 별도 업무 카드가 없다면 비서실이 직접 파악하지 못하는 영역이 있습니다. 모든 변경을 할 일로 복제할 필요는 없으며, 원본 변경 이력과 업무상 중요한 예외를 보고 근거에 연결해야 합니다.

### 출고와 선적 감시

`server/watch.ts:49`의 입출고 조회 조건은 `log_type=eq.inbound`입니다. 현재 이 조회만으로 출고 잔량, 미선적, 도착 지연을 판단할 수 없습니다. 입고 완료를 고객 납품 완료로 취급하지 않고 출고와 도착의 원본 상태를 각각 확인해야 합니다.

### 브랜드별 업무 범위

`client/src/components/Layout.tsx:86`과 `:97`에서 OEM과 브랜드 메뉴가 같은 생산 오더 화면으로 이동합니다. `client/src/pages/ProductionOrders.tsx:411`의 화면 목록 필터에는 workspace 조건이 없고, 신규 생성 경로 `:912`, `:1027`은 OEM 공간을 고정합니다.

또한 `server/work.ts:190`의 개인 AI용 기획전 조회에는 업무 카드처럼 별도 가시성 필터가 붙어 있지 않습니다. 직원 공개 전 브랜드 범위를 검수해야 합니다. 실제 운영 DB의 행 접근 제한과 현재 직원 비공개 설정을 검증하지 않았으므로 운영 중 정보 유출이 발생했다고 판정하지 않습니다. 직원별 메뉴와 API 권한표 작성은 기존 보류 상태를 유지합니다.

### 대표 결정과 팀장 대행

`server/work.ts:420`은 동일 업무 팀의 팀장과 대표에게 확인 요청 대행 답변을 허용합니다. `loadForActor`의 팀 비교가 있으므로 다른 모든 팀장이 답할 수 있다는 뜻은 아닙니다. 다만 대표에게 배정된 요청을 팀장이 대신 닫지 못하도록 별도 경계를 확인해야 합니다.

지시의 실무 완료 보고와 대표 승인을 구분해야 합니다. 팀장이 팀 업무 완료를 기록하는 것까지 일괄 금지하는 설계는 제안하지 않습니다.

### 샘플과 품목 연결 실패

`client/src/pages/ItemMaster.tsx:1856`부터 샘플과 품목을 연결하는 경로에서 연결 실패를 잡은 뒤 품목 등록 성공만 표시하고 연결 식별자를 지웁니다. 품목 자체 저장 성공과 샘플 연결 실패를 분리해 알려야 하며 재시도할 연결 정보도 남겨야 합니다.

## 실사용 통과 조건

각 시나리오는 입력한 원본 ID, 처리자, 변경 전후 상태, 알림 수신자, 다음 기록 ID, 보고 근거를 함께 확인해야 합니다. 화면 성공 표시와 DB 저장 결과가 다르면 통과가 아닙니다.

| 시나리오 | 끝까지 확인할 사항 |
|---|---|
| W컨셉 미결정 요청 | MD 입력 → 팀장 또는 대표 배정 → 답변 → 작성자 회신 → 비서실 결정 근거 |
| 기획전 20퍼센트 확정 | 확정값 → 운영캘린더 → 마케팅과 물류 공유 → 준비 항목 → 현재 보고 |
| 확정 후 날짜와 할인 변경 | 과거 결정 보존 → 현재 원본 반영 → 관련 팀 전달 → 오래된 보고 구분 |
| 샘플 접수와 일정 이동 | 본사와 중국 구분 → 사진과 브랜드 → 관련 디자인팀 조회 → 변경 전달 |
| 브랜드 생산 의뢰 | 의뢰 원본 → 대표 승인 대기 → OEM 수주 → 납기 회신 → 브랜드 조회 → 비서실 |
| 생산과 자재 구매 | 확정 사양 → 수량과 컬러별 소요량 → 구매 → 자재 지연 → 납기 위험 보고 |
| 입고와 출고 | 부분 입고와 검수 → 위치별 재고 → 부분 출고 → 선적과 도착 → 미완료 보고 |
| 대표 지시 | 근거 확인 → 팀 지시 → 직원 알림 → 회신 → 대표 확인, 임의 승인 대행 차단 |
| 연결과 저장 실패 | 입력 보존 → 실패 표시 → 중복 생성 없는 재시도 → 보고에서는 판단 보류 |
| 하루 천 건 규모 | 25명 입력 → 원본 중복 없는 집계 → 공유를 완료로 세지 않음 → 팀 보고 누락 없음 |

운영 ERP는 현재 로그인 화면까지만 확인했습니다. 격리 브라우저 테스트에 필요한 PostgreSQL 런타임과 클라이언트 경로도 이번 환경에서 확보하지 못했습니다. 실제 인증 계정과 격리 저장 환경을 확보하기 전에는 이 표 전체를 실행 통과로 표시할 수 없습니다.

## Claude 지적의 판정 구분

- 채택한 소스 보완 대상: 브랜드 승인 대기 조회, 원본 변경 감시, 출고와 선적 감시, 브랜드 범위, 대표 결정 대행 경계, 샘플 연결 실패 표시.
- 추가 검증 대상: 중국 샘플실 실제 필드와 접근 경로, 운영 SQL의 알림 수신자, PMS 응답, 구글 전송, 실제 AI 보고의 준비 완료 오판.
- 보류한 추정: 팀장 전원이 타 팀 업무를 처리한다는 해석은 현재 팀 비교와 맞지 않습니다. 일정 준비 구분도 코드에 감시 로직과 테스트가 있어 프롬프트만 존재한다고 단정하지 않습니다.
- 삭제하지 않을 후보: 과거 URL 리다이렉트는 호환 기능이므로 단순 잔재라는 이유만으로 제거하지 않습니다.

## 다음 처리 순서

2. 검수용 로그인과 격리 데이터 환경에서 원본부터 비서실까지 실행 증거를 수집합니다.
