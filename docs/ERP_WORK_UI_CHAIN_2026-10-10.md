# 직원 업무 화면 연결 검증

## 수정
- 업무 피드: 첫 조회 전에는 로딩 표시, 조회 실패 시 기존 목록 유지 및 실패 안내. 실패를 업무 없음으로 표시하지 않는다.
- 피드와 업무 비서: 보이는 탭에서 1분 주기·포커스 복귀·탭 복귀 시 조회. 늦은 과거 응답은 새 조회 결과를 덮지 않는다. 화면을 떠나면 타이머·리스너를 해제한다.
- 업무 피드 숫자를 업무함 탭에도 전달한다. 읽음과 완료는 별개다.
- 여러 페이지를 펼친 피드는 기존 조회 끝 지점까지 다시 읽은 후 한 번에 반영한다. 추가 페이지의 답변 초안은 React 카드 키로 유지한다. 중간 조회 실패·다른 계정 응답·반복 커서·100페이지 상한에서는 부분 목록으로 성공 처리하지 않는다.
- 추가 페이지 조회는 이미 진행 중인 갱신을 무효화한다. 조회 끝 지점은 사용자 ID에 연결하며 계정 변경 시 첫 페이지부터 시작한다. 응답 순서가 교차해도 새 페이지·초안을 덮어쓰지 않는다.
- 업무 비서는 전송 시 expectedUserId를 함께 보낸다. 서버는 인증된 사용자와 불일치하면 분류·업무 조회·저장 전에 409/session_changed로 차단한다. 기존 클라이언트의 생략 요청은 호환성을 유지하므로 모든 외부 클라이언트의 작성자 의도를 보장하는 규칙은 아니다.
- POST는 90초 후 클라이언트 대기를 종료한다. 서버 저장 취소를 뜻하지 않으며 원문·ID를 보존해 같은 요청으로 확인한다. 인증 만료·계정 변경도 보존 기록을 지우지 않는다.
- 다른 작성자의 성공 응답은 완료로 인정하지 않는다. 계정 전환 시 작성 초안은 초기화하고, 이전 요청이 대기 중이면 새 계정의 전송 버튼과 입력칸도 잠근다.
- 개인 업무 GET은 브라우저 캐시를 사용하지 않는다.
- 화면 배치·폰트·색상은 변경하지 않는다. 로딩·계정 확인 상태와 갱신 동작만 달라진다.

## 검증
| 범위 | 결과 및 한계 |
|---|---|
| 실제 React 화면 구성 | WorkHub·WorkFeed·WorkChatWidget·CardActions 사용. API·저장소만 메모리 fixture로 대체 |
| 확인 → 답변 → 일정 등록 | 읽어도 open 유지, 답변 후 완료·할 일 감소, 사람이 고친 20% 및 공유 팀이 전송되어 캘린더 캐시에 반영 |
| 실패와 재시도 | 90,000ms 제한 설정을 확인하고 수동 abort. 저장 후 응답 유실·잘못된 JSON·계정 불일치 후 동일 원문·ID 4회, fixture 업무 1건 |
| 계정 변경 | 전송 중 A→B 입력/버튼 잠금. A의 요청을 B 세션에서 거절. 원래 A 계정 복귀 후 같은 ID 확인 및 보존 기록 정리 |
| 자동 갱신 | 주기·포커스·탭 복귀, 숨긴 탭 중단, 오래된 응답 차단, 추가 페이지 답변 초안·부분 조회 실패·응답 교차 보호, 계정별 서로 다른 날짜 범위, 화면 종료 시 정리 |
| 서버 인증 경계 | 실제 requireUser와 서명된 합성 Bearer 토큰을 거친 로컬 HTTP. 다른 기대 ID·빈 ID·null·객체 4종 모두 409, 인증 조회만 1회, 모델/저장 요청 0회 |
| 기존 재사용 | 기대 ID 생략·일치 요청 모두 같은 기존 업무 재사용 및 알림 재전송 계약 유지 |
| 전체 회귀 | TypeScript 177건·JavaScript 10개 테스트 파일 통과. 타입 검사·운영 빌드 통과 |

공유 팀 선택 및 캐시 계약은 화면에서 검증했으나 fixture의 draft/tasks 값으로 실제 서버의 팀 준비 상태를 증명하지 않는다. 공유와 팀 완료 구분은 기존 서버·실모델 검증 기록을 별도로 참조한다.

## 제한과 보호
- 운영 직원 계정·실제 업무·실제 거래·실제 재무자료에는 테스트 입력을 하지 않는다. 직원 사용 잠금·법인원장·보호된 발주 연동은 그대로다.
- 이 검증은 운영 브라우저의 실제 로그인→실제 DB 저장→실모델 보고를 한 번에 실행한 E2E가 아니다. 이전 격리 HTTP/DB 및 실제 모델 검증과 구분한다.
- 페이지 간 목록·집계는 DB 한 트랜잭션의 스냅샷이 아니다. 실패 시 기존 화면을 유지하고 최신 조회 성공을 기다린다.
- 그래프는 기존 legacy WorkflowGuide/store 후보만 제공했다. 현행 화면·서버 호출부를 직접 대조했다. 탐색 예산 600토큰, 그래프 질의의 별도 모델 호출 없음.
