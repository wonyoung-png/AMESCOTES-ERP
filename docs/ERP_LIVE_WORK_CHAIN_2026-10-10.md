# 실제 AI·로그인·저장소 연결 검증

## 범위

운영과 분리된 빈 PostgreSQL/PostgREST에 합성 계정 5개를 만들고 실제 session/work/ceo 라우터로 로그인·업무 입력·답변·일정 확정·팀 공유·대표 보고를 연결한다. 모델 응답을 가짜로 대체하지 않는다. 실제 Google OAuth와 실제 브라우저 화면 전체 클릭은 이 검증에 포함하지 않는다.

## 결과

최종 격리 HTTP/DB/실모델 연결 시험은 통과했다. 운영 배포 확인은 별도 단계이며, 브라우저 전체 E2E가 완료됐다는 뜻은 아니다.

| 검증 | 결과 |
|---|---|
| 인증·권한·업무 입력·팀장 답변 | 실제 쿠키 로그인 및 DB 저장, 잘못된 역할·중복 재시도 차단 |
| 확정·캘린더·팀 공유 | 초안 30% 보존, 확정 20% 저장, 공유팀 실제 계정으로 조회 |
| 읽음·미읽음 | 본인 1 감소, 반복 읽음 불변, 타인 자료 불변 |
| 질문·확정 근거 답변 | 실제 모델 답변 저장; 20% 및 두 팀 준비 미확인 |
| 대표 본인 결정 | 대표 배정 유지, 직원의 대신 완료 차단 |
| 대표 보고 | 마케팅·물류 실제 모델 보고 2개 생성 후 DB 재조회 일치, 공유를 준비 완료로 집계하지 않음 |
| 회귀 | TypeScript 194건·JavaScript 11파일, 타입 검사·운영 빌드 통과 |
| 운영 보호 | 금융 표 4종 신규 행 0, 운영 직원 잠금 true·healthz 정상, 합성 환경 제거 |

- 최종 SSM `b55c325a-be21-447f-9a47-ffec65c965d2`: Success, `liveModelHttpDatabase=PASS`, 검사 그룹 12개, 실제 모델 호출 7회(분류 4·답변 1·보고 2).
- 실제 모델 로그: `claude-sonnet-5-5` 분류/보고, `claude-opus-5-5` 근거 답변. 원래 30% 제안과 확정 20%를 구분했으며, 자료 부재를 준비 미완료로 단정하지 않았다.
- 최종 정상 시험 전에는 검사 도구의 표현 처리 때문에 중단된 시험들이 있었다. 이 실패들을 성공 횟수로 합산하지 않았다. 같은 이름의 합성 스택은 매번 폐기한 뒤 빈 스키마에서 다시 만들었다.
- 한 실행은 자동 배포 잠금을 획득하지 못해 자원 생성 전에 종료됐다. 이후 최대 60초 잠금 대기 후 다시 실행했다.
- 예상된 에러 출력은 중복 일정 확정의 400/`already:done` 차단과 일부러 연결하지 않은 PMS 조회 경고다. 이것을 실제 PMS 연동 성공으로 보지 않는다.

## 발견 및 보완

- 실제 보고가 팀 업무 카드 부재를 근거로 “미준비로 보이며”라고 추정했다. 자료가 없다는 사실은 미이행의 증거가 아니다.
- 팀 보고 지시를 보강했다. 실제 준비 완료·미완료 근거가 없으면 팀명을 포함한 “준비 미확인 — 준비 진행 기록이 없습니다”로 보고한다.
- 직원 챗봇의 근거 답변도 같은 불확실성 표기를 사용하도록 맞췄다. 보고/답변의 실제 모델 전송 지시를 기존 SDK 경로 단위 검사에서 확인한다.
- 업무 카드의 확정 할인율과 운영캘린더의 draft 진행 상태는 별개임을 명시했다. 원문 제안 30%와 확정 20%를 새 할인 결정 요청으로 되돌리지 않는다.
- 초기 시험은 실제 AI의 “기록에 없습니다”, “두 팀/각 팀의 준비 완료 기록은 없습니다”, “기록을 찾지 못했습니다”를 검사 도구가 인식하지 못해 중단됐다. 이를 운영 기능 결함으로 간주하거나 전체 통과로 보고하지 않았다.
- 반대로 20%라는 글자가 포함되기만 한 역전된 답변, 한 팀만 미확인인 답변, 다른 절에서 준비 완료를 주장한 답변이 통과하지 않도록 음성 회귀 사례를 추가했다. 한국어 의미 판정 전체를 증명하는 도구가 아니라 이 합성 시나리오에 한정된 검사다.

## 안전 경계

- 내부 DB망과 별도의 모델 통신망을 사용한다. DB/API/runner는 고정된 테스트 이름·라벨이며 공개 포트·운영 볼륨이 없다. 기존 동일 이름이 있으면 재사용하거나 정리하지 않고 시작을 거절한다.
- 운영 DB에서 스키마·역할·권한만 읽어 복제하며 실제 행·비밀번호 해시·회사 업무를 복제하지 않는다. 테스트 인증키와 비밀번호는 새로 생성한다.
- 실제 모델 키는 서버 밖으로 가져오거나 파일에 저장하지 않는다. 서버의 기존 앱 프로세스에서 테스트 runner의 stdin으로 전달하고 프로세스 메모리에만 설정한다. SSM 요청·실행 결과·Docker 환경 설정에 실제 키 값을 넣지 않는다.
- 네트워크 호출은 테스트 REST·루프백·정확한 모델 messages 주소만 허용하고 리디렉션을 차단한다. 기존 요청 signal과 60초 제한을 결합하고 모델 전송은 실행당 최대 10회로 제한한다.
- 운영 직원 잠금은 true로 유지한다. false는 합성 사용자만 있는 테스트 runner에만 설정한다. 실제 거래·재무자료 생성, 금융 테이블 삭제, 법인원장 변경은 하지 않는다.
- 자원 생성 전 EXIT 정리 등록. 기존 테스트 정리 스크립트의 이름·라벨·마운트·포트·망 구성원 검사를 거쳐 합성 DB/컨테이너를 폐기하고, 별도 통신망은 라벨과 빈 구성원을 확인한 뒤 제거한다. 합성 자료는 복구용으로 보관하지 않는다.

## 재실행

- `scripts/e2e-live-work-harness.ts`: esbuild Node CJS 번들로 만든 뒤 서버 stdin으로 전달하는 테스트 전용 진입점. production index와 자동 스케줄러는 실행하지 않는다.
- `scripts/e2e-live-work-run.sh`: Docker 호스트에서 실행. `ERP_E2E_EXPECTED_HEAD`에 검토한 서버 소스 커밋을 명시하고 검토한 번들을 stdin으로 공급한다. 배포 잠금을 최대 60초 기다린다.
- `scripts/e2e-work-http.ts`: 기본 모의 모델 검사와 실제 모델 검사에서 동일한 로그인·저장·권한 검증을 재사용한다. 저장된 보고, AI 실패, 미저장 결과를 별도로 확인한다.
- `server/work-http-evidence.test.ts`: 팀별 불확실성·부정 표현 및 초안/확정 역전 회귀 검사.

## 제한

- 실제 모델은 ERP에 구성된 Anthropic 모델이다. Codex 대화에 선택한 모델과 ERP 런타임 모델은 별개다.
- CEO 추가 증명은 새 테스트키로 서명한 합성 ceo_g다. 실제 Google 로그인·콜백 성공을 검증한 것이 아니다.
- PMS·Google·메일·Slack은 연결하지 않는다. PMS 경고는 고의로 차단한 외부 의존성의 결과이며 PMS 데이터 정확성 검증이 아니다.
- 실제 브라우저 구성 요소의 이전 모의 API 검사와 이번 실제 HTTP/DB/AI 검사를 합쳐 하나의 브라우저 E2E라고 표현하지 않는다.
- 예약 시각 자동 보고, 실제 25명 동시 사용, 실재고/SKU 대조, 금융 실자료·법인원장은 별도 또는 보류 범위다.
- `graphify` 기존 그래프는 현행 서버 경로를 충분히 표현하지 않아 직접 소스와 실행 결과를 대조했다. 그래프 질의 예산 600토큰이며 별도 모델 호출은 없다. `karpathy-guidelines`에 따라 변경은 보고 지시와 검증 도구로 제한했다.
