# 실제 로그인·HTTP·DB 연결 검증 — 2026-10-10

## 결과

격리된 빈 DB에서 금융 업무와 챗봇·비서실 업무를 같은 실행으로 통과했다. 운영 회사 자료에 거래·알림을 생성하지 않았고, 고객 화면·운영 기능 코드는 변경하지 않았다. 추가한 것은 검증 스크립트와 기록이다.

최종 업무 결과는 12개 검사 그룹 통과, 모델 fixture 응답은 7회, 확정 근거가 포함된 질문/보고 프롬프트 검사는 3회다. 전체 회귀는 TypeScript 107건(기존 브라우저 검사 포함)·MJS 7파일·타입 검사·운영 빌드 통과. 새 HTTP 시나리오는 이 단위 테스트 개수와 별도로 실행했다.

## 무엇이 실제이며 무엇이 모의인가

- 실제: 현재 소스의 session/work/ceo/receipt/payable 라우터, HTTP 요청, 쿠키 서명·검증, PostgREST, PostgreSQL 함수, 저장 후 DB 재조회, 기존 월별 자금계획 집계 함수.
- 모의: Anthropic 응답은 정해진 합성 응답이다. 대신 실제 답변/보고 함수가 전달한 확정 근거를 검사한다. 실제 모델의 이해·품질을 이번 실행으로 입증하지 않는다. 이전 별도 실제 모델 5분류·1보고 검사는 전 보고서의 독립 증거다.
- 모의: Google OAuth 대신 새 테스트 서명키로 만든 합성 ceo_g 증명을 사용한다. 실제 Google 로그인·콜백 성공은 검증하지 않았다. 증명 없는 접근 및 직원 접근 차단은 실제 verifier로 검사했다.
- 제한: PMS는 연결하지 않았으며 조회 실패 경고가 발생했다. 테스트 REST 프록시는 실제 PostgREST의 anon 역할을 사용하지만 운영 Caddy/Express 전체 배치를 재현한 것은 아니다.
- 제한: 운영과 같은 스키마·함수 및 역할 이름/상속/권한을 복제했지만 객체 소유자·역할 속성 전체를 동일하게 복제하지 않았다. 운영 권한 완전 재현·운영 로그인 후 화면 전체 클릭·예약 시각 자동 실행 검증이라고 표현하지 않는다.
- 추가 보고의 통과는 정상 샘플이고, 실제 여러 사용자 동시 HTTP 요청 부하는 이번 범위가 아니다. 지난 별도 DB 25세션 동시성 검사와 구분한다.

## 실행·안전 증거

- 내부 Docker 네트워크 `erp-e2e-20261010`, DB/API/runner 3개 모두 `codex.e2e=20261010` 라벨, 공개 포트 없음, 생산 네트워크/볼륨/환경 파일 미연결.
- DB는 tmpfs, 운영에서는 스키마와 역할/권한 읽기만 수행했다. 운영 행·계정 해시·실제 서명키·API 키를 복제하지 않았다. 새 임시 DB/인증 비밀을 생성했으며 출력하지 않았다.
- 정상 DB 프로세스 준비 후 복제하고 Bash pipefail로 덤프·복원 실패를 감지한다. 대상 URL/격리 표식 검사와 빈 계정표 검사 후에만 합성 계정을 만든다. DROP/DELETE 없이 별도 DB에만 합성 자료를 저장했다.
- HTTP 검사 과정에서 초기 테스트 도구의 DB 초기화 준비 판단, 지급 재전송 기대값, Node fetch의 Host 덮어쓰기 문제를 보완했다. 운영 코드 결함을 발견해 수정했다는 뜻은 아니다.
- Node fetch가 custom Host를 무시해 CEO 테스트가 404였던 원인은 테스트 도구 문제였다. CEO 요청만 검증된 루프백의 native HTTP로 보내며 Host·Origin·추가 증명 검사를 우회하지 않는다. 리디렉션은 따라가지 않는다.
- 초기 금융 단독 통과와 업무 resume 디버깅 통과는 참고 자료다. 최종 통과는 새 빈 스택의 기본 모드에서 금융과 업무를 함께 실행한 결과만 인정한다.
- 최종 스택 준비 SSM: `6a411bf4-d544-4d0f-a8cd-b93bc814b876`; 최종 통합 실행: `992b746d-a43e-44c3-9c26-f6abd75b366b` — Success, `isolatedHttpDatabase=PASS`.
- 정리 스크립트는 고정 이름·라벨·내부망·포트·마운트·망 구성원을 먼저 검증한다. 정리 결과 확인 후 합성 자료만 폐기하며 실제 회사 자료는 삭제하지 않는다.
- 최종 정리 SSM `9ff20b98-62d6-4e6c-bafb-6114c291b776` — Success, 스택 3개와 테스트 내부망 제거 완료. 합성 자료는 복구용으로 남기지 않았다. 운영 HTTPS `/healthz` 200 유지.

## 재검사 파일

- `scripts/e2e-isolated-bootstrap.sh`: Docker 호스트에서 Bash로 실행, 같은 이름이 존재하면 재사용하지 않고 중단.
- `scripts/e2e-http-harness.ts`: esbuild로 Node CJS 번들 생성(`packages=external`, `.html=text`), 검증된 runner의 stdin으로만 실행. production index와 자동 스케줄러는 실행하지 않는다.
- `scripts/e2e-finance-http.ts`, `scripts/e2e-work-http.ts`: 실제 HTTP 연결 검사 함수; production import/route가 아님.
- `scripts/e2e-isolated-cleanup.sh`: Bash로 명시적 대상 검증 후 중지·제거. 전체 Docker prune/생산 DB 행 삭제 없음.
- `ERP_E2E_RESUME_WORK=1`은 정확한 합성 계정 ID가 있을 때만 쓰는 디버깅 옵션이다. 금융·초기 시드를 생략하므로 결과는 `WORK_DEBUG_PASS_NOT_FULL_RUN`; 전체 통과 근거로 사용하지 않는다.
