# 비서실 보고·협의 근거 최신성 — 2026-10-10

## 결과와 사용 방식

- 대표 전용 비서실에서 저장된 보고와 현재 조회 근거를 비교한다. 동일한 날 생성된 보고라도 일정·할인·업무·감시 기준·직원 업무 범위가 바뀌면 `근거 변경 · 다시 점검 필요`로 표시한다.
- `저장 근거와 일치`는 해당 보고의 입력 범위가 현재 조회 결과와 일치한다는 뜻이다. 회사 전체 자료를 전수 검증했거나 조회 이후 변경까지 확인했다는 뜻은 아니다.
- 과거 메타데이터 없음, 원천 조회 실패, 연결된 캘린더 없음/조회 불가, 매출 자료 미수집·원화 값 미확인은 `최신 근거 확인 불가`로 구분한다.
- 보고 생성과 비교가 같은 조회·규칙·팀 분류를 사용한다. SHA-256 근거 지문은 기존 `team_agent_runs.stats.evidence`에 저장한다. 기존 보고를 덮어쓰지 않는다.
- 조회만으로 보고를 새로 생성하거나 AI를 호출하지 않는다. `지금 점검`으로 새 보고를 생성하며 기존 일일 자동 점검 스케줄은 유지한다.
- 일부 업무/직원/감시 기준 조회 실패 시 기존 보고를 비서실에 유지하되 실패 배너와 미확인 상태를 표시한다. 원천이 불완전하면 새 보고·협의 생성은 중단한다.
- 대표 질문에서 검색한 과거 업무도 연결된 현재 캘린더를 다시 조회한다. 당시 결정과 현재 상태를 분리한다.

## 협의·지시

- 협의 근거는 시작일·주제·팀·근거 내용을 포함하며, 매 조회마다 달라지는 조회시각은 비교에서 제외한다.
- 같은 시작일·같은 근거는 DB 고유키로 중복 생성하지 않는다. 변경된 근거는 새 협의로 남기며 실패 재시도도 새 ID를 사용한다. 기존 결론·발언은 수정/삭제하지 않는다.
- 협의 시작일과 근거를 저장/실행/충돌 조회에 고정해 자정 이후 완료되더라도 오늘의 새 협의로 오인하지 않는다.
- 변경·미확인·과거 일자 협의는 `이 안으로 지시` 버튼을 표시하지 않으며 서버에서도 지시를 거부한다. 브라우저가 확인한 근거 해시도 서버에서 대조한다.
- 협의에 포함됐다는 이유로 팀 보고의 대표 확인 사항을 숨기지 않는다. 과거 협의는 전체 이력에서 보존하고 현재 결정 목록에서는 제외한다.
- 같은 팀의 여러 제안은 하나의 지시로 합쳐 내용 손실을 방지한다. 협의 ID·팀에 대한 고정 업무/알림 ID로 동시 요청·응답 유실·협의 전달 기록 저장 실패 재시도를 중복 없이 처리한다.
- 충돌 재사용 시 출처와 본문을 검사하고 기존 저장 담당자를 사용한다. 알림은 INSERT만 수행하며 기존 읽음 표시를 수정하지 않는다.
- 지시 자체가 근거 조회와 단일 DB 트랜잭션으로 묶이는 것은 아니다. 판단 범위는 조회 시점이며 근거가 이후 다시 변경되면 재점검이 필요하다.
