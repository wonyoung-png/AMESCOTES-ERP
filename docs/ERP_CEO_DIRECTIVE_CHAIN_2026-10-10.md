# 대표 지시 → 완료 → 팀 보고 → 비서실 검증

## 범위 및 변경
- 대표실 지시는 요청 ID로 재시도하며 같은 ID의 다른 내용은 거절한다.
- 팀 계정의 이름과 실제 소속이 모두 일치해야 배정한다. 미일치 시 대상 팀의 전달 대기로 남긴다.
- 기존 지시는 검증된 대표 작성자와 directive.team으로 조회/팀장 권한을 판정한다. 과거 DB team은 수정하지 않는다.
- 대표 지시는 종류 변경을 막고 결과 기록/완료/취소로 처리한다.
- 생성 알림과 대표에게 보내는 완료 알림은 업무 저장과 같은 트랜잭션의 outbox로 기록한다. 전송 장애는 업무를 다시 작성하지 않고 재전송한다.
- 새 생성 알림은 notificationVersion=1에만 적용한다. 기존 앱의 수동 생성 알림과 중복되지 않는다. 기존 지시의 이후 완료에는 완료 알림을 적용한다.
- DB readiness RPC가 없는 구 DB에서는 새 지시/완료를 저장하기 전에 503으로 차단한다. SQL 먼저 적용 후 앱을 교체한다.
- 브라우저 임시 재시도 캐시는 대표 계정별이다. 팀/화면 이동과 새로고침에도 요청 ID를 유지하며 응답 검증 후 제거한다. 캐시 저장 차단 시 전송하지 않았다고 표시한다.
- 완료자/완료시각은 결과 메모가 없어도 AI 근거에 포함한다.
- 업무 UUID를 품번으로 오인해 협의를 묶던 정규식을 단어 경계로 제한했다.

## 제한 및 보호
- 모델 답변은 결정적 테스트 응답이다. 실제 AI 답변 품질/실제 Google OAuth/실제 PMS 통신 성공을 주장하지 않는다.
- 테스트는 내부 전용 네트워크, 임시 DB, 합성 직원 계정만 사용했다. 실제 직원 잠금/실제 재무자료/법인원장/보호된 발주 연동은 변경하지 않는다.
- 운영에는 테스트 지시/보고/알림을 생성하지 않는다. 테스트 환경은 검증 후 정확한 이름과 라벨 확인 후 폐기한다.
- 알림 SQL 회귀 및 전송 중 취소 잠금 검증 통과: SSM `0781611d-429c-48a8-b233-1fb8ef918d22`, Success. 기존 생성 알림 중복 방지, 미배정/취소 지시 제외, 완료 결과/기존 읽음 보존 확인.
- 브라우저 저장 장애가 재시도 중 발생해도 이전 요청 ID를 버리지 않는 회귀 검증 통과.
