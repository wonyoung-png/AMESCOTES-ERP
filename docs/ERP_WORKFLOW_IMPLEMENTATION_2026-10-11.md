# 실제 ERP 업무 흐름 구현·검증

## 적용 범위

정적 UI 시안이 아니라 기존 ERP의 샘플관리·업무함·생산발주·자재구매·미지급·지출·비서실 소스를 수정했다. 새 업무 탭은 추가하지 않았다. 기존 거래명세표·BOM·작업지시서·입출고 기능은 유지했다.

**운영 서버 배포와 운영 DB 마이그레이션은 아직 실행하지 않았다. 실제 회사 자료·재무 자료·직원 계정은 변경하지 않았다.** 4184 포트의 정적 시안은 실제 ERP 소스 및 인증·DB 기능과 별개다.

| 업무 | 구현 위치와 연결 |
|---|---|
| 샘플 완료 | 원본 샘플 상세에서 사진 등록 후 `완료` 한 번. 완료 시각은 서버 저장, 달력 접수·마감일은 유지 |
| 팀장 수락 | 지정 제품개발 팀장의 업무함에 원본 링크 생성. 별도 확인요청 버튼 없이 전달. 제품명·등록 바이어/브랜드·청구가격 수정 후 수락 |
| 샘플 청구 | 수락 전 서버 차단. 단건 및 완료월 취합, 같은 바이어의 미청구 명세표에 추가 가능. 사진·원본 ID·기존 명세표 행 보존 |
| 청구 취소·재시도 | 미청구 명세표의 해당 샘플 행만 제거. 발행·수금 전표 차단. 재시도는 같은 원본 연결 재사용 |
| 재샘플·상품/BOM | 기존 상품 등록/BOM 연결 유지. 다음 차수는 새 완료·수락·사진·청구 상태로 시작하고 이전 차수 유지 |
| 본사 사입 자재 발주 | 기존 업체별 자재발주 경로 유지. 규격·통화·단가·환율별 구분. USD를 CNY로 변환하지 않음. 부분 실패 후 환율을 고정해 재시도 |
| 자재 재고 | 같은 실물 자재의 재고는 가격별 장바구니 행 사이에 한 번만 배분 |
| 작업지시서 | 기존 9열 양식·서명·수기 번호·메모 유지. 해당 색상 BOM 누락 시 다른 색상 자재 차용 금지 및 전달 기록 차단 |
| 불량 차감 | 입고 불량 후보는 추정치로 유지. 공장 책임·확정금액·사유 확인 후 같은 입고/발주/공장 미지급에서 1회 차감. 재작업 제외 |
| 승인 경비 연결 | 승인 접수에 연결된 계좌이체 경비를 기존 미지급으로 연결. 예정일 입력 후 기존 자금계획에서 조회. 승인 근거 없는 일반 경비는 자동 연결하지 않음 |
| 비서실 | 완료 대기·수락 후 미청구를 원본 샘플 ID로 보고. 완료한 샘플은 작업 지연에서 제외. 현재 원본의 가격·바이어·청구·승인 변경을 최신성 근거에 포함 |

## 보호 장치

- 완료·수락·청구는 서버 인증 및 최신 DB 사용자 권한 검사. 브라우저가 전달한 사용자 ID는 사용하지 않는다.
- 샘플 완료·청구·불량 차감·경비 연결은 DB 트랜잭션으로 처리하고 재시도 시 중복 생성하지 않는다.
- 수락된 샘플의 일반 메모·체크리스트 수정은 버전 조건부 UPDATE로 저장한다. 샘플 삭제 성공 전에는 화면 캐시에서 제거하지 않는다.
- 연결된 원본 삭제·수금 전표 수정·다른 거래처 연결·변경된 자료 확정·잔액 초과는 차단한다.
- 기능 마이그레이션 또는 서버 연결이 없으면 준비 전 안내를 표시한다. 실패를 로컬 저장 성공으로 대체하지 않는다.

## 검증 방식과 한계

| 최종 검증 | 결과 |
|---|---|
| 화면·업무 함수·API·기존 흐름 회귀 | 165개 통과 / 실패 0 |
| 격리 PostgreSQL SQL·불량/경비 보호 동시 적용 | 11개 통과 / 실패 0; 실제 다중 연결 경합 검증은 별도 |
| 실제 샘플 React 화면 + 모의 DB API | 사진 없는 완료 차단, 저장 실패 후 재시도, 직원/팀장 구분, 수락 후 청구 버튼 연결 통과 |
| 모바일/데스크톱·라이트/다크 | 샘플 컴포넌트 390/1440px 가로 넘침·실행 오류 없음; 전체 ERP 디자인 승인 아님 |
| TypeScript 및 클라이언트/서버 빌드 | 통과; 기존 큰 번들·혼합 import 경고는 남음 |

- 실제 수정 함수·서버 라우터를 실행하는 회귀 테스트, 실제 React 샘플 컴포넌트의 브라우저 조작, 임시 PGlite의 실제 PostgreSQL SQL 실행을 병행했다.
- 브라우저 샘플 검증은 DB 어댑터를 모의 처리했다. PostgreSQL 검증은 별도 격리 DB에서 실행했다. 이를 운영 DB 종단간 검증으로 간주하지 않는다.
- 기존 USD/CNY 원가·상품 연결·명세표·입출고·자금계획·비서실 보고 회귀를 확인한다. 개별 테스트의 통과는 운영 권한과 운영 데이터의 정상성을 보증하지 않는다.
- 독립 Codex 검토에서 자재 재고 중복 사용·환율 재시도·레거시 가격 식별·같은 환율 계약의 수량 누락, 원본 삭제·바이어 구분·수락 샘플 보고 근거, 승인 경비 보호 우회 및 승인 전/후 불량 미지급 보호를 발견해 보완했다. 수정 후 최신 회귀검사를 다시 실행했다. Claude 검토는 이번 범위에서 실행하지 않았다.
- 최종 독립 재검토: 샘플/비서실(Kepler), 자재발주(Tesla), 승인 경비(Kuhn), 불량 차감/지급(Wegener). 최신 수정본에서 추가 재현 P0/P1 없음. 작업지시서 선택 문제는 실제 함수/부모 전송을 실행하는 회귀 및 부모 통합 검토로 확인했다.
- SQL 검증은 임시 설치한 PGlite 모듈의 절대 경로를 `SAMPLE_TEST_PGLITE`·`DEFECT_TEST_PGLITE`로 전달해 실행했다. 테스트 스크립트는 `.env`와 운영 DB에 접근하지 않는다. 운영 패키지/잠금 파일은 변경하지 않았다.

### 마이그레이션 순서

운영 적용 전에 기존 테이블·열·권한을 확인한다. 신규 마이그레이션은 격리 DB에서만 실행했다.

1. 기존 `migration_work_notification_outbox.sql`과 기존 지급·입고 마이그레이션 선행 여부 확인.
2. `migration_purchase_material_spec.sql`, `migration_sample_workflow.sql` 적용.
3. 기존 `migration_payable_payment_atomic.sql`보다 **뒤에** 최신 `migration_defect_approval.sql` 적용.
4. `migration_expense_payable.sql` 적용. 불량·경비 트리거의 동시 적용을 테스트했다.
5. PostgREST 스키마 캐시 반영, 서버·클라이언트 반영 후 실제 계정/격리 업무 자료로 검증. 기존 지급 마이그레이션을 마지막에 재적용하면 최신 지급 보호가 덮어써지므로 금지.

## 운영 적용 전 남은 항목

1. 기존 DB 트리거·권한·마이그레이션 선행 조건 및 기존 중복 미지급 여부를 확인하고 백업 후 적용한다. 중복 발견 시 삭제하지 않고 중단한다.
2. 테스트 전용 계정·격리 자료로 샘플→수락→명세표→상품/BOM→발주→입출고→미지급→비서실의 전체 실제 ERP 화면을 검증한다.
3. 기존 완료·청구 이력이 새 수락 필드를 갖지 않은 레거시 샘플은 확인 없이 수락·미청구 예정액으로 자동 판정하지 않는다.
4. 공장 전달 시 작업지시서의 불변 버전 자동 보존·외부 전송 성공 확인은 이번 변경에 포함하지 않았다. 현재는 실제 전달 여부를 사용자가 명시적으로 확인한 기록이다.
5. 회사 재무자료 입력·법인원장 분리·직원 공개는 대표님의 기존 결정대로 후순위로 유지한다.
6. 작업 브랜치와 원격 `aws-migration`의 기존 이력이 분기되어 있으므로 운영 통합 전에 원격 변경을 검토한다. 검증 결과만으로 다른 세션의 변경을 덮어쓰거나 즉시 배포하지 않는다.
