# 업무 알림 전달 복구 — 2026-10-10

## 범위와 결과

- 확인 요청 생성·담당 재배정·답변·일정 확정의 알림 의도를 업무 변경과 같은 DB 트랜잭션에 보존한다.
- 애플리케이션이 저장 직후 종료하거나 알림 전달에 실패해도 업무를 다시 만들지 않는다.
- 즉시 전달 실패 후 서버 시작 시/매 60초에 재시도한다. 네트워크 대기는 10초로 제한한다. 장애가 지속되면 대기 상태를 유지한다.
- 같은 제출 ID의 기존 조회 및 동시 생성 충돌 두 재사용 경로에서도 해당 업무 알림만 다시 전달한다.
- 전달 이벤트 ID는 DB에서 독립 생성해 보존한다. 전달 시 같은 ID로 INSERT만 수행하고 읽음·본문을 덮어쓰지 않는다.
- 취소·결정 완료·재배정으로 무효가 된 대기 확인 요청, 비활성 수신자는 억제 사유와 함께 종결한다.
- 수신자와 확정 본문은 발생 시점 사본이다. 팀 공유와 작성자 중복은 하나로 합치고, actor ID로 확정자를 제외한다. 동명이인 이름은 비교하지 않는다.
- 업무→outbox 순서로 잠근 뒤 최신 상태를 검사한다. 다른 작업이 잠근 행은 SKIP LOCKED로 다음 재시도까지 보존한다.

## 보안 및 보존

- 신규 outbox 테이블은 RLS 활성화, PUBLIC/anon/erp_server 직접 접근 차단. 고정 search_path의 제한된 서버 전용 전달 RPC만 사용한다.
- 업무·기존 알림·읽음 표시 삭제/수정 및 과거 알림 일괄 재발송은 없다. 새 트리거 적용 이후 발생한 변경부터 적용한다.
- 구독 확인(subscriptionCheck)과 대표 별도 지시의 기존 알림 경로는 이번 대상에서 제외해 중복 전송을 피한다.
- 재무 실자료 입력, 법인 원장 분리, 직원 개방은 진행하지 않는다. ERP_PRIVATE_MODE=true를 유지한다.
- 화면 구조는 그대로다. 전달 실패 문구만 “저장 완료 / 알림 전달 대기 / 자동 재시도”로 변경한다.
