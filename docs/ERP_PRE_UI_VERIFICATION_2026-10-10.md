# UI·UX 전 기능 검증 — 2026-10-10

## 판정

자동으로 안전하게 검사 가능한 아래 범위는 통과했다. 이 결과를 ERP 모든 기능의 실사용 검증 완료나 UI·UX 착수 조건 전체 충족으로 해석하지 않는다. 실재고 대조·과거 자료 판단·실제 로그인 거래 전 과정은 별도 확인이 남는다.

## 이번 수정

- 자금계획: 옛 상태명이 완납이어도 청구액보다 수금액이 작으면 상세·예상 잔액에서 제외하지 않는다. 월별 합계와 같은 실제 잔액 기준을 사용한다.
- 브랜드 리오더: 위치·불량·현재 주문 수요를 구분하지 못하는 과거 입출고 차액을 현재고·가용·권장 리오더로 표시하지 않는다. 미확인으로 표시하고 재고 대조로 연결한다. 배송처 숫자는 과거 출고 이력이라고 명시한다. 원본 발주·이력은 삭제하지 않았다.
- 중국창고: 첫 전송 종류·본문·ID를 고정해 응답 유실 후 변경 재전송을 막는다. 사용자·브랜드별 탭 세션에 전송 전에 저장하며, 같은 탭의 페이지·브랜드 전환·새로고침 후 복구한다. 세션 저장/복구 실패는 새 전송을 차단한다. 성공 또는 근거 확인 후 명시적 해제만 허용한다. 다른 탭·기기·브라우저 종료 후 복구를 보장하는 서버 공용 잠금은 아니다.
- 서버의 분류 함수와 순수 보고 생성 함수는 격리 모델 검사에 사용할 수 있도록 export만 추가했다. 테스트는 실제 업무 저장·runAgents·알림을 실행하지 않는다.

## 실행 증거

| 범위 | 결과 | 구분/한계 |
|---|---|---|
| TypeScript 회귀 | 105건 통과 | 실제 함수·구조 검사·합성 자료 및 중국창고 화면 2건 포함 |
| 추가 화면 회귀 | 2건 통과 | 실제 React 화면, 신규 격리 Chrome; HTTP 응답/저장은 모의 |
| 기존 저장 회귀 | 7파일 통과 | 캐시·실패·버전 비교·재시도 계약; 모의 API |
| 타입 검사·운영 빌드 | 통과 | 기존 큰 청크·정적/동적 import 경고는 남음 |
| 기존 SQL 회귀 | 11파일 통과 | 생산 스키마만 복제한 빈 격리 DB; 실자료 미복제 |
| 발주→입고→출고→청구→부분 수금/지급→완료 | 추가 SQL 8검사 그룹 통과 | 문서 ID·번호·잔액 0 직접 검사, 전체 롤백 |
| 청구 동시성 | 실제 DB 25세션×40건, 1,000건 | 번호 1,000개 유일, 연결 미수금 1,000건·총 1,100,000원 |
| 출고 경합 | 25건 중 20성공·5초과 차단 | 100개 발주에 5개씩 경합; 동일 ID 재시도 24건, 원본 1건 |
| 수금 경합 | 1성공·24오래된 원본 차단 | 동일 요청 재시도 25건에 추가 누적 없음 |
| 일일 업무 규모 | 직원 25명×52건=1,300건 합성 | 전체 페이지·팀 집계·확정 근거·한국 자정 검사; 생산 응답속도 보증 아님 |
| 실제 LLM | 분류 5가지·팀 보고 1가지 통과 | 합성 원문만 제공; 실제 Anthropic 모델 호출, ERP 거래/알림 없음 |

기존 SQL은 첫 실행에서 리오더 검사에 필요한 기존 품목 fixture가 없어 중단했다. 격리 DB에 합성 품목을 마련한 뒤 나머지 검사를 재실행해 11파일 모두 통과했다. 동시성 최종본은 새 `erp_preui_recheck` DB에서 재실행했으며 8.97초는 격리 환경 관측값이지 생산 부하 SLA가 아니다.

AI 보고의 초안 수치 언급 자체를 실패로 보던 초기 검사는 잘못된 기준이었다. 초안임을 표시하면서 확정값으로 정정하는 설명은 허용하도록 수정했다. 최종 실제 응답은 10/20 확정 할인율 20%, 마케팅 준비 근거 없음, 공유 일정은 마케팅 완료 실적이 아님을 명시했다. 제목·요약·대표 확인 사항까지 함께 검사했다. 이는 모든 질문·보고의 정확성을 보장하지 않는다.

## 안전 경계

- 테스트 컨테이너 `erp-preui-test-20261010`: `codex.preui=20261010` 라벨, 네트워크 none, 공개 포트 없음, tmpfs 및 별도 DB만 사용했다.
- 운영 DB에서는 스키마·권한 읽기만 수행했다. 생산 행을 복제하거나 거래·승인·알림·DELETE/DROP를 실행하지 않았다.
- DB 동시성 fixture는 다른 세션 확인을 위해 격리 DB에만 커밋했다. 테스트 컨테이너 정리 시 이 합성 자료만 폐기한다.
- 화면 테스트는 사용자 브라우저·ERP 로그인 창과 별도 프로필로 실행했다. 중국창고 재시도 화면의 모의 API와 실제 DB 함수 동시성 증거를 혼동하지 않는다.
- 법인 원장 분리·직원 개방·은행/외부 회계 연동·AETALOOF 확장은 보류 유지한다. ERP_PRIVATE_MODE는 해제하지 않는다.

## 닫지 않은 항목

| 항목 | 필요한 확인/후속 |
|---|---|
| 이지어드민 실재고 | 동일 시각 I100/실재고 자료, SKU·창고·불량·가용 의미 대조. 저장된 PMS 재고 표만으로 API 계약을 확정할 수 없음 |
| 과거 중복 일정·이력 | 동일 업무인지 대표/담당자 판단 후 통합. 자동 삭제·합치기 금지 |
| 중국→한국 부분 도착 | 현재 전량 도착만 지원. 부분 도착 규칙·잔여 운송 수량 모델은 미구현 |
| 실제 로그인 거래 전 과정 | 격리 SQL 연결 검사는 통과했지만 실서버 발주부터 최종 수금까지 클릭 저장은 실행하지 않음 |
| AI 전체 경로 | 분류·순수 보고 생성은 실제 모델, 질문 답변 검색→응답·예약 실행→저장→대표 전달 전체 연결은 미검증 |
| 금융 일괄 복원 | 한 파일 전체 원자성은 보장하지 않음. 개별 저장 실패·캐시 보호 증거와 구분 |
| ERP/PMS 저장소 | 화면·인증 통합과 백엔드/저장소 통합은 다름. 별도 운영 자료의 소유권 연결은 남음 |

이 항목을 완료로 바꿀 때는 새 증거를 기록한다. 전면 UI·UX 개편은 제외하며, 정합성·재시도 관련 화면 수정은 포함한다. graphify의 오래된 연결 후보는 현재 소스로 대조하고, ponytail·karpathy-guidelines에 따라 원본 보호·최소 변경·검증 범위를 적용했다.

## 운영 확인

- 기능 커밋 `8c36fc5`를 aws-migration에 반영하고 배포 잠금 하에 app만 빌드·교체했다. 컨테이너 내부 `/healthz` 및 외부 HTTPS 상태 200, 컨테이너 이미지와 빌드 이미지 일치, `ERP_PRIVATE_MODE=true`, 익명 중국 재고 조회 401을 확인했다.
- 라벨·정확한 이름·네트워크 none·tmpfs 외 마운트 없음·공개 포트 없음을 확인한 뒤 테스트 컨테이너를 중지·제거했다. 합성 DB 자료만 폐기했으며 운영 회사 자료는 변경하지 않았다. 이 테스트 자료는 복구용으로 보존하지 않았다.
