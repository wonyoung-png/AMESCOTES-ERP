# Claude 운영 반영 전 검토 — 실제 실행 결과

공통 Invoke-ClaudeReview.ps1를 별도 병합 worktree에서 실제 실행. exit0, 성공 결과. 비용 USD1.11. 읽기 전용 정적 검토이며 운영 적용/실환경 승인 아님. 아래는 반환 결과의 요약과 Codex 조치 기록입니다.

## 차단 판정

Claude는 DB·코드 전환 순서/롤백, 전체 신규 마이그레이션 선행 조건, 광고 Cafe24가 의존하는 DB15, 최신 구독 배정 보존 확인이 필요하므로 당시 push·DB 적용을 중단하라고 판단했습니다. 분석 비활성 상태 선반영은 코드상 가능하다고 판단했습니다.

## 지적 및 현재 대응

1. **승인 충돌:** 대표님이 Codex 직접 배포·DB 적용 질문에 ‘응’으로 답한 현재 대화 승인으로 운영 담당 변경. ADS_ROLLOUT_EXECUTION.md에 명시. Claude 검토 실행기에는 쓰기 권한 없음.
2. **자동 배포/DB 전환:** 자동 배포 파이프라인 유지. 새 이미지 빌드 준비와 기존 DB/함수·트리거 백업, 짧은 단일 전환 및 롤백 검증 전 운영 쓰기 시작하지 않음.
3. **선행 DB:** 알림/지급/입고/정산→purchase spec→sample workflow→defect approval→expense payable→sample settlement→DB15→DB016을 검수해야 함. 운영 정확한 함수/열을 직접 추가 점검 중.
4. **Cafe24 DB15:** channel_tokens가 필요. DB15와 전용 앱 토큰 미등록을 각각 구분하며 미확인 상태를 성공으로 보고하지 않음.
5. **구독 최신 변경:** origin/aws-migration을 부모로 병합. subscriptions.ts 및 watch.ts의 팀장→경영지원 배정을 diff와 회귀로 확인 중.
6. **비활성 만료알림:** 현재 스케줄러는 ADS_ANALYSIS_ENABLED=false면 만료 알림도 실행하지 않음. 11월10일 이전 연결 완료 또는 분석과 독립된 알림 보강 필요.
7. **실계정 검수:** ERP_PRIVATE_MODE=true 유지로 직원 공개 차단. 실제 직원·승인자 종단간 검수는 수행했다고 주장하지 않음.
8. **활성화/비용:** 09시 이후 켜면 즉시 두 시장 접수 가능. Opus 단가/계정/시장 매핑 확인 전 활성화하지 않음.
9. **루트 TLS:** Caddy에 루트 호스트 블록이 없는 정적 원인 후보. ERP 서브도메인 광고 반영과 별도 이슈.

Meta GET 고정, 광고 주문 리더의 상품 쓰기/OAuth 갱신 차단, 비활성 요청503/러너401, 대표 비서실의 DB 미설치 오류 처리, 광고 테이블 권한 및 일일 중복 방지는 정적으로 문제없다고 판단했습니다.
