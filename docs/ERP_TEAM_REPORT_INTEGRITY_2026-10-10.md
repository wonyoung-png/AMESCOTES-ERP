# 직원 업무 → 비서실 일일 보고 무결성

## 반영 내용
- 실제 팀 보고 작성기가 AI 응답의 end_turn·빈 본문·필수 필드·needs 구조를 확인한다. 여러 text 블록은 연결해 읽는다.
- 불완전 응답·JSON/형식 오류·AI 키 없음은 규칙 집계와 원본 확인 안내만 저장한다. stats.reportAvailable=false 및 evidence.complete=false로 남아 현재 정상 보고로 표시되지 않는다.
- 근거 없는 팀은 모델을 호출하지 않는 규칙 보고로 처리한다. 정상 보고와 구분 없이 실패로 재시도하지 않는다.
- 보고의 cardId 링크는 모델에 실제 제공한 표본 내 카드만 허용한다. 전수 숫자와 AI 표본은 기존대로 분리한다.
- 일일 자동 점검은 새 fallback-only 기록을 성공으로 세지 않는다. 다음 주기에서 빠진 팀을 재시도한다. 과거 reportAvailable 미기록 행은 기존 성공 기록으로 호환한다.
- 일일 점검 기록은 페이지 조회하며 임의 100건 제한으로 이미 성공한 팀을 놓치지 않는다.
- 생성·일일 점검의 대상 목록을 통일한다. 조직도 팀 외 실제 팀 미지정 업무도 포함하며 대표실·질문·취소만 있는 추가 팀은 제외한다.
- 한 팀의 저장 실패가 뒤 팀 점검을 중단하지 않는다. 성공 집계에는 정상 보고만 포함한다.
- 화면 배치·폰트·색상 변화 없음. 기존 비서실의 미확인 표시에 실패 보고도 연결한다. 직원 잠금·법인원장·보호된 발주 연동 변경 없음.

## 검증
- 신규 테스트는 실제 writer·Anthropic SDK·loadReportContext·runAgents를 실행하되 모든 HTTP를 합성 응답으로 가로챈다. 저장 요청도 메모리에서만 받는다.
- 정상·여러 text 블록·토큰 제한 중단·빈 응답·요약 없음·needs 형식 오류·JSON 오류·키 없음의 저장 결과와 재시도 대상 구분을 확인한다.
- 빈 팀의 무모델 처리, 첫 팀 저장 실패 후 뒤 팀 계속 진행, 팀 미지정 대상과 기존 보고 호환성을 확인한다.
- 운영 직원 계정·실제 업무·실제 재무자료에 테스트 쓰기 없음. 실모델 문장 정확도나 운영 로그인→실DB→AI 전체 E2E를 이 테스트로 증명하지 않는다.

## 범위 및 한계
- 자동 보고는 기존 KST 08:30 이후 점검·10분 주기이며 외부 메신저 전송 기능을 추가하지 않는다.
- 다중 컨테이너 DB 잠금·외부 스케줄러 이전은 별도다. 현재 프로세스 내 중복 실행 보호를 유지한다.
- 정상 보고 후 자료 변경은 기존 근거 해시/미확인 표시와 수동 점검을 따른다. 이번 변경은 실시간 자동 AI 재작성 기능이 아니다.
- 과거 reportAvailable 미기록 보고의 문장 완성도를 소급 판정하거나 데이터를 덮어쓰지 않는다.
- 그래프 질의 work/report/daily는 과거 store·daily-bridge 후보를 제공했다. 현행 agents·work-records·ceo-console을 직접 대조했다. 질의 예산 600토큰, 별도 그래프 모델 호출 없음.
