# 서버 이전 런북

## 왜 옮기나

지금 ERP 는 **비그로우 AWS 계정**(858695669700)에 세 들어 있다. 2026-10-08 확인:

- 같은 계정에 비그로우 자사(`bgrow-web`, `bgrow-os`)와 **다른 고객사 7곳**의 서버가 같이 있다
- 그쪽이 root 를 쥐고 있으므로, IAM 사용자를 빼도 우리 DB·비밀값을 그대로 본다
- 계정을 통째로 넘겨받는 것도 안 된다 — 남의 고객사가 같이 들어 있다
- 매일 DB 전체 백업이 그쪽 계정 S3(`amescotes-erp-ops-858695669700`)로 간다

재무 기능을 넣기 전에 끝내야 한다.

## 옮기기 전에 끝낸 것

- `atlm-hr` 소스 회수 (2026-10-08). 빌드 이미지가 그쪽 ECR 에만 있어서 떠나면 다시 빌드할 수
  없는 상태였다. 돌던 컨테이너에서 꺼내 `wonyoung-png/atlm-hr` 비공개 레포로 올렸다.

## 순서

### 사람이 먼저 (결제가 붙어서 대신 못 한다)
1. **ATLM 명의 AWS 계정** 생성 + 카드 등록
2. **`ameserp.kr`** 도메인 등록 (카페24 — `atlm.kr` 과 같은 곳이라 DNS 가 한 군데로 모인다)
3. 서버 1대: `t4g.medium`(2vCPU·4GB) · 디스크 **40GB** 이상
   - 지금 서버가 30GB 중 86% 라 여유를 더 둔다
   - 보안그룹은 **80·443 만** 연다. SSH 는 안 연다 (SSM 으로 들어간다)
4. IAM 키를 알려주면 나머지는 내가 한다

### 그다음 (내가)
5. `bash bootstrap.sh ameserp.kr` — 도커·스왑·소스·비밀값·기동까지
   - 중간에 배포키 공개키를 뱉는다. 레포 3개에 읽기 전용으로 넣고 다시 실행
   - `.env` 의 빈 항목(앤트로픽·구글)은 **새로 발급한 값**으로 채운다. 옛 값 재사용 금지
6. DNS A 레코드 5개를 새 서버 IP 로
   `erp` · `ceo` · `daily` · `hr` · `os` → 새 IP
   (HTTPS 인증서는 Caddy 가 알아서 받는다. DNS 가 먼저 붙어 있어야 한다)
7. 새 주소로 들어가 **빈 ERP 가 뜨는지** 확인

### 전환 (일 안 할 때)
8. 옛 서버에서 덤프 3개
   ```
   docker compose exec -T db pg_dump -U postgres erp | gzip > erp.sql.gz
   cp /opt/app/daily-data/daily.db  daily.db
   cp /opt/app/hr-data/hr.db        hr.db
   ```
9. 새 서버로 올린 뒤 `bash cutover.sh /덤프폴더`
10. 눈으로 확인 → DNS 전환 → **옛 서버 자동배포 타이머 끄기**
    (안 끄면 양쪽이 같이 돌면서 글이 두 군데 쌓인다)
11. 하루 지켜보고 비그로우에 옛 서버·S3 백업 삭제 요청

### 마무리
12. 비그로우를 `AMESCOTES-ERP` 협업자에서 제거 + 레포 **비공개** 전환
    - 지금 당장 하지 않는 이유: 어차피 root 로 다 보이고, 먼저 끊으면 그쪽 작업만 멈춰
      이전이 늦어진다. 이전이 끝나는 날 한 번에 끊는다
13. 옛 키 전부 폐기 — 앤트로픽·구글 OAuth·DB 비밀번호 (그쪽 서버 `.env` 에 있던 10개)

## 되돌리기

DNS 를 옛 IP 로 돌리면 끝이다. 옛 서버는 13단계 전까지 그대로 둔다 — 지우지 않는다.
단 전환 뒤에 새 서버에 쌓인 입력은 되돌리면 사라진다. 그래서 전환은 일 안 할 때 한다.
